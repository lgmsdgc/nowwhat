# STEP 6 검증 기록

2026-10-07. Supabase 프로젝트가 없는 환경에서 구현·로컬 검증을 진행했습니다.

## 구현

- 완료 2회 이후 선택적 저장 안내, `/account`와 최근 기록, 가입·로그인 구분.
- Google 연결/기존 계정 로그인, Email 연결·로그인과 링크·OTP, PKCE callback.
- 익명 ID 유지 가입, 기존 계정으로의 서버 전용 일회용 증명 이관.
- 계정별 RLS, 원자적 세션·피드백·EXP 이관과 재시도 중복 방지.
- 로컬 완료 기록 보관, 원본 유지, source 표시, 로컬 EXP를 서버 보상에서 제외.
- 계정 전환 시 이전 화면 데이터·응답·대기 명령 차단.

## 자동 테스트

`npm test`는 단위 90개 + 실제 PostgreSQL 통합 22개 = 112개입니다.
기존 86개 테스트에 계정 서비스 단위 11개, callback 복구 4개, DB 이관·보관 테스트 11개를 추가했습니다.

단위 검증:

- 익명 소유권 준비 후 Google identity 연결, 기존 계정 OAuth 분리.
- Email updateUser와 기존 로그인 shouldCreateUser=false, 올바른 OTP 유형.
- 현재 SDK의 sb_flow_id 전달, 증명 준비 실패 시 로그인 중단.
- callback의 동시 실행 병합, 인증 코드 재소비 없이 이관 재시도, 네트워크 교환 재시도, 인증 후 새로고침 복구.
- 이관 실패 시 증명 유지, 성공 뒤에만 제거, 만료·손상 증명 갱신.
- 로그인 중 로컬 원본 전송·삭제 없음, 명시적 보관 후에도 원본 보존.
- 완료 세부 정보만 선별, 로컬 EXP·제목 제외, 잘못된 소유권·과다 기록·소유자 주입 거절.

PostgreSQL 검증:

- 같은 ID의 익명→회원 전환은 기록·EXP 유지.
- 두 계정의 완료 기록·피드백·보상을 합치고 미션 UUID 유지, 재시도 중복 없음.
- source 읽기·쓰기 차단, 다른 사용자에게 증명 재사용 거절.
- 목적지 PLAY 충돌 종료, 충돌이 없으면 기존 미션 이어하기.
- 만료·위조·익명 목적지 거절, 브라우저의 ticket 조회와 쓰기 RPC 호출 거절.
- 중간 오류에서 전체 이관 롤백 및 증명 재시도.
- 복수 증명의 같은 목적지 재시도, 동시 대기 증명 수 제한.
- 로컬 기록 제목 검증·비용·평가·코멘트 보관, 중복 없음·EXP 추가 없음.
- 보관 기록 RLS 격리·직접 쓰기 거절, 일부 기록 오류면 전체 보관 롤백.

Auth 서비스는 테스트용 포트와 SQL 인터페이스를 사용했습니다.
실제 Supabase Auth·Google OAuth·메일 발송·PostgREST 연결을 테스트한 것으로 해석하지 않습니다.
원격 설정·확인 절차는 `docs/account-setup.md`에 있습니다.

## 실행·모바일 검증

최종 `npm run check`의 포맷·ESLint·타입·112개 테스트·production build가 통과했습니다.
별도 production origin `127.0.0.1:3001`에서 기존 테스트 기록(완료 3회, 300 EXP)을 사용했습니다.

- 390px 모바일에서 내 기록 화면·기존 완료 링크·가입/로그인 선택을 확인했습니다.
- local 모드의 Google·Email 버튼이 실제로 비활성화되고 기기 저장 안내가 표시됩니다.
- 완료 화면에 저장 안내가 나오며 `나중에`를 누르면 미션 흐름을 막지 않고 닫힙니다.
- callback을 직접 열면 연결 전 상태를 안내하고 가입 화면으로 돌아갈 수 있습니다.
- 모바일 상단 메뉴가 줄바꿈되지 않도록 조정했고 콘텐츠 폭·scrollWidth가 모두 375px로 가로 넘침이 없습니다.
- 브라우저 console error/warn은 없었습니다.
- `GET /api/account`는 local 모드에서 503·no-store로 미설정을 안내합니다.
- sourceUserId를 주입한 prepare POST는 400으로 거절했습니다.
