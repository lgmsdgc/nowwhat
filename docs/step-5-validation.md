# STEP 5 검증 기록

2026-10-06. 사용자가 Supabase 프로젝트 없이 연결 준비와 로컬 DB 검증을 요청한 범위입니다.

## 구현

- Supabase SDK, 명시적인 local/supabase 모드, 공개 키·서버 키 분리.
- 브라우저 익명 Auth와 서버 getUser 검증. 가입과 이관 UI는 다음 단계.
- 7개 테이블, 60개 시드, FK·제약·인덱스, RLS와 명시적 grants/revokes.
- 서버 전용 트랜잭션 RPC, revision 충돌 재시도, 중복 보상 방지.
- 엄격한 명령 검증, 요청 크기 제한, private/no-store 응답, 시간대·서버 시각.
- 로컬 모드 보존, 네트워크 오류 표시, 연결 모드에 맞는 저장 안내.

## 자동 검증

`npm run check`의 포맷·ESLint·타입·86개 테스트·production build가 통과했습니다.
`npm run db:seed:generate`로 SQL 시드를 생성하고 PostgreSQL에 적용했습니다.

통합 테스트 11개는 PGlite의 실제 PostgreSQL에 두 마이그레이션을 실행합니다.
Auth users 테이블, `auth.uid()` SQL 인터페이스, 역할을 테스트용으로 준비한 후 실제 권한을 전환합니다.

- 60개 seed와 모든 동행 관계 일치, 재실행 가능.
- anon의 공개 카탈로그 조회, 개인 기록·초기화 접근 거절.
- 인증된 두 사용자의 프로필·세션·피드백 조회 격리.
- 직접 EXP·세션·칭호 쓰기와 공개 역할의 commit RPC 호출 거절.
- 비활성 미션과 관계 숨김.
- 요청·재추천·수락·체크·완료의 저장, 평가·거절 이유·EXP 유지, 재시도 중복 방지.
- 동시 요청의 revision 충돌 처리, 추천 1개만 유지.
- 오래된 revision 거절, 뒤쪽 피드백 오류 시 앞쪽 세션 쓰기도 롤백.
- 다른 사용자의 ID 덮어쓰기·이력 삭제·완료 보상 수정 거절, 포기 보상 없음.

단위 테스트는 기존 66개에 연결 관련 9개를 추가했습니다.
설정 누락·비밀 키 노출 방지, 입력 주입·잘못된 시간대·16KiB 제한,
비공개 응답·내부 오류 숨김, 명령만 전송, 실패 시 로컬 fallback 없음,
한국 23시 야간 안전 판단, 충돌 재시도 상한을 검증합니다.

## 브라우저와 실행 확인

프로덕션 서버의 별도 테스트 origin(`127.0.0.1:3001`)에서 사용자 프리뷰 기록과 분리해 확인했습니다.
390px 모바일 뷰포트에서 기존 추천 이어하기 → PLAY → 체크 3개 → 완료 입력을 수행했습니다.
금액 `0`과 코멘트는 새로고침 뒤 복원됐고, 완료 시 EXP 100을 지급해 합계 300 EXP/LV.2가 됐습니다.
완료 화면을 다시 새로고침해도 합계가 유지됐습니다. 콘텐츠 폭 375px/scrollWidth 375px로 가로 넘침이 없었습니다.
화면 기록은 `artifacts/step-5-complete-mobile.png`입니다(로컬 산출물, Git 제외).

`GET /api/game`은 기본 local 모드에서 503과 no-store 응답으로 DB 모드 미설정을 안내합니다.
`npm audit --omit=dev` 결과 런타임 취약점은 0건입니다.

## 검증 한계

Supabase 프로젝트가 없으므로 **호스팅된 Auth, PostgREST, 실제 키·원격 마이그레이션 연결은 검증하지 않았습니다**.
PGlite는 실제 PostgreSQL SQL을 실행하지만 Supabase 서비스를 구동하지 않습니다.
프로젝트 생성 후 `docs/supabase-setup.md`의 원격 연결 절차를 수행해야 합니다.
칭호 획득·가입·데이터 이관·분석·배포는 해당 후속 단계에서 구현합니다.
