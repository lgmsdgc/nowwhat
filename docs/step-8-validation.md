# STEP 8 검증 기록

2026-10-07, 기본 local 모드와 실제 PostgreSQL(PGlite)에서 검증했습니다.
원격 Supabase 프로젝트가 없어 실제 Auth·PostgREST·Google/Email·운영 DB 연결은 미검증입니다.

## 구현과 주요 파일

- `types/analytics.ts`, `lib/validation/analytics.ts`: 방문 문맥·이벤트·허용 속성·배치의 명확한 타입과 런타임 검증.
- `services/analyticsService.ts`: 발생 사실 추출, 의미별 중복 제거, 현지 날짜.
- `lib/analytics/visit.ts`, `outbox.ts`, `transport.ts`: 방문 복원·30분 비활동·큐·ACK·전송 포트.
- `services/analyticsClientService.ts`, `components/analytics/AnalyticsBoundary.tsx`: 루트·명령·공유 수집 연결, 실패 격리.
- `services/analyticsReportService.ts`, `scripts/report-analytics.ts`: 5개 핵심 지표와 JSON CLI.
- `app/api/analytics/route.ts`: 인증된 수집·본인 한정 조회.
- `supabase/migrations/202610070004_analytics.sql`: RLS, 서버 전환 이벤트, 입력 재검증, 계정 이관 시 소유자 연결.
- `services/shareService.ts`, `features/gameplay/ShareMissionButton.tsx`: 공개 완료 문구, 네이티브 공유·명시적 복사, 시도/성공 구분.

추천 요청 실패를 노출 성공으로 바꾸지 않습니다. 수락과 시작은 같은 동작의 별개 이벤트이며
완료 재요청은 EXP·이벤트를 중복 지급하지 않습니다. 체크리스트 변경은 분석 이벤트를 늘리지 않습니다.
로컬 보관 기록과 분석 큐를 인증된 다른 계정으로 자동 업로드하지 않습니다.
과거 기록은 소급 방문/노출을 만들지 않으므로 지표 범위와 한도를 함께 해석해야 합니다.

## 자동 검증

단위 134개 + PostgreSQL 통합 43개 = **177개**.

- 방문 새로고침·비활동·역행·저장 차단, 한국 자정 경계와 관찰 중인 D1 제외.
- 비용·코멘트·전체 URL·잘못된 이벤트·과도한 배치 거절, 오래된 v1 복원.
- 미션 노출·거절·수락·시작·완료·포기 사실과 재시도 중복 제거.
- 로컬 게임 저장 실패 시 완료 이벤트 없음, 분석 용량만 문제면 완료·보상 유지.
- 오프라인 큐 유지, 동시 추가 후 ACK, 300개 한도·20개 배치·만료·손상 보존·계정별 격리.
- 분석 전송 실패·SDK/브라우저 오류·공유 취소가 성공으로 집계되지 않음.
- 같은 DB 게임 결과와 TypeScript 이벤트 의미 일치, 실패한 게임 트랜잭션 이벤트 롤백.
- 분석 테이블 저장 오류를 주입해도 게임 완료·EXP·칭호 정상 확정.
- 두 사용자 RLS 격리·직접 쓰기 금지·내부 RPC 권한·가짜 게임 전환/잘못된 소유자 거절.
- 공유 세션의 소유권·완료 상태 확인, 잘못된 배치 전체 롤백, 동일 배치 재전송 중복 제거.
- 계정 이관의 분석 연결·출처 유지·방문 중복 합치기·재시도·실패 롤백.
- 세션 단위 전환율·사용자/흐름별 재추천·D1·공유/복사 분리, 분모 0은 null.

포맷·ESLint·TypeScript·production build를 함께 확인합니다.
테스트는 Supabase 연결 없이 `npm run check`, DB만 `npm run test:db`로 재현합니다.

## 수동 확인 방법

1. 홈에서 시작하고 질문 완료 후 미션을 요청합니다.
2. `한 번만 다시`를 누르면 사유 입력 없이 바로 다른 미션을 받습니다. 거절 사유는 null로 저장하고 횟수는 유지합니다.
3. 수락·체크·완료 후 결과와 EXP를 확인하고 새로고침합니다.
4. 완료 화면에서 공유를 취소하거나 문구와 링크를 복사합니다. 취소는 시도만 남고 성공하지 않습니다.
5. 복사 문구에 제목·EXP·홈 링크만 있고 비용·코멘트·개인 완료 주소가 없는지 확인합니다.
6. 로컬 JSON을 `npm run analytics:report -- records.json`으로 집계합니다.

390×844 모바일 viewport의 인앱 브라우저에서 production 서버 3001을 사용했습니다.
기존 3000 개발 기록은 변경하지 않았습니다. 기존 완료 기록은 과거 코호트로 남겨두고,
새로운 온보딩 → 추천 → 사유 있는 재추천 → 수락/시작 → 체크 → 완료 → 새로고침 → 링크 복사를 확인했습니다.

- 분석 기록 15개: 방문/홈/온보딩 시작/완료 각 1, 요청/노출 각 2, 거절/수락/시작/완료 각 1,
  공유 시도 2, 성공 1. 새로고침으로 방문·완료 이벤트가 중복되지 않았습니다.
- 네이티브 공유 요청은 성공을 반환하지 않아 시도만 남았습니다. 실제 외부 전송은 하지 않았고
  명시적 복사만 성공했습니다. 네이티브 취소·성공 분기는 단위 테스트로 검증했습니다.
- 복사 문구는 `「물건 하나, 전설의 광고」 해냈다! EXP +120`, 브랜드 문구, 공개 홈 링크입니다.
  입력한 코멘트·금액·개인 세션 주소와 익명 ID가 없고 분석 JSON에도 코멘트가 없습니다.
- 실측 clientWidth/scrollWidth는 375/375px로 가로 넘침이 없습니다.
- 분석 기록만 내보낸 `artifacts/step-8-analytics.json`에서 CLI 실행이 성공했습니다.
  노출 2·수락 1·완료 1로 수락률 0.5, 완료율 1, 재추천 1회/흐름 1개,
  복사 성공 세션 1, 네이티브 성공 0입니다. 당일 방문은 D1 관찰 중 1명으로 비율 null입니다.
- 캡처는 `artifacts/step-8-share-mobile.png`이며 임시 읽기 전용 검증 페이지·테스트 탭·3001 서버는 정리했습니다.

위 수치는 기능 확인용 한 사용자의 테스트 기록이며 서비스 운영 성과를 의미하지 않습니다.
