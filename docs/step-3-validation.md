# STEP 3 검증 기록

검증 환경: Node 24 / npm 11, Next.js 16.3.8, 한국어 UI, 390 × 844 모바일 뷰포트.

## 자동 검증

`npm run check`는 Prettier → ESLint → Next 라우트 타입 생성/TypeScript → Vitest → production build를 실행합니다.
Vitest의 비즈니스·저장소 테스트 25개가 다음을 검증합니다.

- 여섯 질문 필수, 무제한과 0원 구분, 입력 검증
- 원본 상태 불변, 미션 스냅샷, 요청·재추천·시작 재시도
- 후보 부족 시 기존 추천 유지, 거절 사유와 횟수 기록
- 체크리스트와 시작 상태 확인, 완료·보상·좋아요 한 번만 기록
- 실제 소요시간, 잘못된 비용·평가·코멘트, 선택적 입력과 작성 중 저장
- 포기 시 EXP 없음, 300 EXP에서 레벨 2
- 모든 동행·강도의 엄격한 조건에 후보 존재, 안전·시간·비용·활동량 상한
- 집과 실내 외출 구분, 시작 시 야간 안전 재검사
- 익명 ID와 질문 복원, 명령마다 최신 저장 문서 읽기
- 쓰기 실패 시 기존 기록 유지, 손상·새 버전 자동 초기화 금지
- 손상 원문 백업 후 복구, 백업 실패 시 기존 기록 보존

## 브라우저 검증

인앱 브라우저에서 실제 UI를 Playwright로 조작했습니다.
독립적인 E2E 테스트 파일을 설치한 것은 아니며, 아래 절차로 다시 확인할 수 있습니다.

1. 혼자 → 15분 → 0원 → 집에서만 → 에너지 1 → 아무거나.
2. 질문 중 새로고침 후 단계와 선택 복원.
3. 미션 하나 생성 → 거절 사유 선택 → 다른 미션, 재추천 횟수 증가.
4. 수락 → PLAY → 일부 체크 → 새로고침 후 체크와 시작 시간 유지.
5. 전체 체크 → 완료 입력 → 음수 금액 제출 차단.
6. 0원·재미 5점·재도전 의사·코멘트 입력 → 새로고침 후 초안 유지.
7. 완료 결과 → 실제 시간·0원·코멘트·EXP +100 → 새로고침 후 중복 보상 없음.
8. 같은 조건으로 다음 미션 생성 → 수락 → 포기 → 완료 수·EXP 유지.
9. 키보드 라디오 조작, 모바일 가로 넘침과 브라우저 오류 확인.

## 현재 범위

기록은 해당 브라우저 origin의 localStorage에만 저장됩니다.
Web Locks를 지원하는 최신 브라우저의 HTTPS/localhost 환경을 사용합니다.
실제 소요시간은 기기 시계 기반이며, 완료는 사용자의 체크와 제출로 기록합니다.
서버가 검증하는 보상·RLS·로그인 이관·칭호·분석은 이후 단계의 범위입니다.
추천 정책은 검수된 16개 템플릿에서 수행 가능성을 먼저 확인하는 수준입니다.
가중 개인화와 60개 seed는 STEP 4에서 검증합니다.
